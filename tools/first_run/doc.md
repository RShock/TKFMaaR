# 自动更新与配置迁移

## 同目录更新

- 桌面发布包复用 MFAAvalonia 的 GitHub 更新器及文件事务，不另造下载和安装器。只检查 `RShock/TKFMaaR`；保留自动检查和资源自动更新的用户选择，资源自动安装默认关闭，可主动开启。前端和 native runtime 由本项目完整包统一维护，不单独自动升级。
- 发布包不包含 `config/` 或根 `appsettings.json`。启动模块在前端读配置前只补缺失的默认键，不覆盖 false、空清单、实例顺序、定时、设备或任务选项；已有任务结构迁移继续使用各模块的一次性版本标记。
- 自定义图片保存在安装目录的 `userdata/resource/image/UserStages/`，作为第二个资源包加载；原有 `UserStages/...` 引用和配置ID不变。原生更新器只清理 `resource/` 和 `agent/`，不能再把用户截图当成运行资源删除。发布构建不得携带维护者配置或用户图片。
- `UserDataMigration.cs` 在资源加载及更新检查前，自动复制旧资源中的用户图片到持久目录，核对同名内容和保存的引用。复制不删除旧图；冲突、缺图或配置损坏时停止启动并说明原因，不清空配置或回退默认值。
- 首次启用、新版本首次启动、缺失默认键或有待迁移图片时，先备份 config、appsettings、userdata 和旧图到 `backup/userdata-*`，成功后更新 `.tkfm-userdata.json`。该备份发生在设置迁移前；更新覆盖保护依靠包中不含用户数据及目录隔离，不能声称这是旧进程更新前的备份。
- 已发布的1.5及以前版本仍会在启动新版前清理旧截图，不能由新版远程补救。首次接入须先关闭旧助手，把修复版完整包解压到同一文件夹再启动，保留原 config、appsettings 和旧图；之后才可持续使用程序内原地更新。已丢失的图片只能从旧目录或备份恢复。

## 商城配置

- 读入实例文件后逐个迁移旧商城任务。已有商品勾选和折扣开关以磁盘值为准。确认是旧版两组清单时，按商品名拆分。缺失选项由界面补默认。写入前和本次其他实例变更一起备份。开发版和发布版使用同一入口。

## 启动游戏与 ADB 重连

- 备份后一次性把现有“启动游戏”移到任务首位，并修正已保存的勾选状态。用户已经删除的任务不自动添回。
- 模拟器启停选择归入“启动游戏”。旧版自动派遣开关归入“每日派遣”，保留已有选择与按倒计时生成的预约，清理旧手填时间。“每日派遣”已有选择时优先保留。旧手填程序作为已保存设备的内部兼容数据。清理助手曾自动写入的原生启动路径，保留用户手动设置的原生路径。
- `ScheduleBootstrap` 等前端主窗口就绪后调用前端原有扩展加载器，允许关闭模拟器时使用定时任务和测试按钮。开发版和发布版均从当前 Interface 的资源目录加载。

## 桌面界面配置

- 前端读取配置前，在备份后的默认配置与命名配置中移除旧 GitHub Token，标记跳过首次使用教程。代理设置沿用保存值。Windows 同时移除旧的最小化与关闭托盘开关值，窗口行为由前端扩展固定。

## 故障诊断

- 备份后固定原生 `maa_option.json` 中的 `save_on_error=true`，使首次连接前已启用故障截图。设置页的导出按钮调用桌面启动组件。
- `ErrorLogExport` 读取最近 72 小时有更新的日志原文件和故障截图，在日志目录的 `exports` 下写入单个 ZIP。正在写入的日志按打开时的长度复制，导出成功后发布文件并打开对应位置。

## Windows 后台扩展

- 定时启动引导在编译资源扩展前加载 Windows 注册表程序集。托盘与登录自启设置随扩展加载并独立于模拟器连接。启动组件不注册自启动项。

## 可选的跨目录导入

- 正常启动和升级不自动显示向导。仅Windows用户在安装根目录主动创建 `.tkfm-import-request` 后，下一次启动才进入旧版跨目录导入；完成或取消后删除请求。保留原 libloader，不修改 EXE/DLL。原一次性展示标记仅保留历史记录，不再决定日常启动行为。
- 用户先打开旧助手，向导每1.5秒按进程完整路径和安装目录中的 TKFMaa/TKFMaaR 元信息自动检测。唯一来源直接识别，不显示选择列表；多个来源才要求选择，刷新保留仍然有效的选择。始终由用户点击导入后才结束旧助手。排除当前程序及重叠目录；启动时间、进程句柄和完整路径共同限定待结束进程。
- 导入整个 config、根 appsettings.json 和旧 interface 指向资源中的 image/UserStages，图片写入新版 userdata/resource/image/UserStages。保留截图相对路径，检查配置引用及截图文件，不复制旧版代码、interface 或运行库。旧目录内的绝对路径调整到新目录，外部模拟器路径保持原值。
- 先暂存并检查完整资料，再结束用户选定的旧助手，重新读取落盘数据，备份新版数据后导入。失败回滚已替换文件，旧目录始终保留；取消不结束进程、不导入数据。无法读取进程或截图缺失时提示失败并允许刷新或取消。
- 启动模块使用前端自带 .NET；全部桌面矩阵安装 net8.0 启动程序集和部署配置。仅跨目录向导依赖Windows和PowerShell，导入器使用发布包 Python 及一并打包的 json-with-comments，不能依赖维护者的虚拟环境。
- 必须先备份 config、appsettings.json 和用户截图再升级，不能将向导等同于停电／磁盘损坏保护；未保存到磁盘的旧版编辑无法保证继承。新建配置及迁移的定时设置需由用户复核，不由迁移工具启动游戏。
- 向导随启动它的前端退出而关闭；导入器持有单独文件锁，后续启动在读配置前等待导入结束。开发强制重启遇到正在导入时停止重启，空闲向导按本目录脚本参数及前端父进程精确结束；若向导已随父进程退出则跳过，不能把退出中的空路径误报为进程身份改变。
