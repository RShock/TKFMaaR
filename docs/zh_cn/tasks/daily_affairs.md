# 每日政务扫荡（DailyAffairs）

“消耗体力”先执行已开启且到期的政务扫荡，再进入原配置的内置或自定义关卡。`daily_affairs.json` 负责页面路由，`agent/daily_affairs.py` 负责当前画面决策、动态数量与跨恢复保留的资源账目。

## 选项和资源约束

- “扫荡战争演习”“扫荡情报搜集”“扫荡商业经营”三个开关默认开启。旧配置仅补缺项，保留明确关闭；运行中修改下次队列生效，全部关闭直接走原路线。
- 三项各自按最近一次确认扣券的本地日期间隔三天。24 日确认扣券，27 日起可再扫荡。无记录时可执行。每日任务完成后可分别获得一张门票，每项最多存三张。三项均未到期时直接进入原配置的体力关卡。
- 顺序为战争演习特IV、情报搜集高、商业贸易特IV。情报只有初、中、高，不寻找不存在的IV；缺少最高关不降级打普通高耗体关卡。
- 三项只扫荡，独立于后续关卡的“使用扫荡券”开关。每项最多3次，满票共9次；只用现有门票、体力和扫荡券，无票或资源不足正常跳过。不买资源、不用药、不普通战斗。

## 页面流转

1. 出征 → 目前活动 → 每日政务 → 进击 → 分类 → 最高关。按当前画面决定动作，允许从中途页面继续；列表最多下滚6次。
2. 列表已确认本类门票为0且没有待核账的提交，直接跳过。有票时只选名称与等级标记在同一张卡上的唯一候选：情报为Lv.40，战争和商业为Lv.60。详情再核对标题、难度后缀、对应门票及军团扫荡按钮，门票和体力足够才打开设置。
3. 识别“自动扫荡设置”，先点击右侧菱形MAX，再重新读取“扫荡N次”、门票、扫荡券和体力预览。数量必须是现有资源允许的最大值且为1–3次，门票与扫荡券分别减少N、余额非负，才点“扫荡开始”中点。不能点击相邻的“购买扫荡券”。体力预览不要求严格差N，避免自然回复或显示时序误差，但当前必须足够、预览非负。
4. 识别扫荡结果后点“完成”，回到同关详情核对门票按预期扣除，才记录完成。随后城堡回主页，处理下一项；全部处理且确认无遮挡主页后进入 `DailyStaminaBattleStartAttempt`。

“军团扫荡”可在不同位置。弹窗标题与“扫荡开始”文字分别用实图定位，在两者之间找每种资源上下两行的图标，再读取图标右侧的数字，不要求入口、标题、提交按钮或资源列在固定横坐标。多次布局在选择栏内找MAX和次数；单次布局的资源行紧接标题，且最多能扫1次、三项预览各减1才提交。读数或布局不明确时不提交。

分类、最高关行、详情标题、门票图标、MAX、提交和结果按钮均使用ADB内部截图归一720×1280后裁出的实图，位于 `DailyAffairs/`。OCR仅用于动态次数与资源。点击采用识别框精确中点、按钮局部300毫秒稳定等待与短超时。

## 恢复和完成依据

- 看到同类的错误关卡详情，只点左上返回到列表重选。一个分类的同一导航动作已发出三次仍需重做，就跳过这项，日志给出原因，继续后续安排；已提交的次数不会重发。稳定等待中画面有变化，回到识别入口再决定；持续变化有20秒上限。

- 恢复包装器在首次尝试前通过 `initialize` 初始化一次；局部恢复及游戏重启保留选项、已处理项、预占次数、待确认提交，不重新发放资源额度。
- 每个实例分别持久化各分类的确认扣券日期，并从同实例的近期日志补录旧记录。无票、资源不足和未确认扣券的提交不更新日期。
- 提交前预占次数。资源扣除不符，或20秒仍未确认时，记录未确认并跳过本项。
- 初始已有扫荡设置而缺少本轮进入依据时，先关闭后重识别详情；初始已有扫荡结果只关闭，不冒领当前分类的完成记录。
- 业务识别排除已知遮挡，让统一恢复处理广告、公告及网络异常；未知画面连续20秒未识别才进入原返回、系统返回及故障策略。
- 开发版和发布版均只补三个新开关，保留旧关卡、自定义图片与其他选项。手工采集的流程证据不代表新增代码已通过自动执行。
