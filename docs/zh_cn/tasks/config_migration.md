# 自动更新与配置继承

正常升级继续使用同一个安装文件夹和原生GitHub更新器，不要求打开旧助手，也不自动显示导入向导。以下持久目录和自动迁移逻辑随修复版发布包生效；已经发布的1.5不具备这些保护。

## 同目录更新

1. 新版继续自动检查 `RShock/TKFMaaR`。用户确认安装，或自行启用“自动更新资源”后，复用原生下载、文件事务与重启流程；默认不自动安装，也不单独升级前端/native运行库。
2. 更新包不包含 `config/`、根 `appsettings.json` 或用户截图，因此不会用发布默认值覆盖原配置。
3. 新版读取配置前自动备份并迁移数据：旧资源图片复制到 `userdata/resource/image/UserStages/`，作为第二资源包加载。已有的 `UserStages/...` 相对引用和配置ID保持不变。
4. 全局设置仅补缺失键；已有任务继续使用一次性结构迁移，新增选项按默认值初始化，已有勾选、取消、空清单和输入值保留。迁移不启动游戏、不重发资源消费额度。
5. 首次启用、版本变化或需补数据时，保存 `backup/userdata-*`，完成后登记 `.tkfm-userdata.json`。配置损坏、图片缺失、内容冲突或复制失败时停止启动并给出原因，保留旧资料及备份。

原生更新器全量更新只清理 `resource/` 和 `agent/`，独立的userdata不会被当作程序资源删除。迁移备份发生在新版启动、配置结构变换之前；安装阶段的数据保护来自目录隔离及更新包不含用户文件，不能把启动备份称为旧进程安装前备份。

## 从1.5或更早版本首次接入

旧版更新器在启动新版前就会删除旧资源中的截图，新版无法远程改变已经运行的旧逻辑。首次接入请保存设置、关闭旧助手，将修复版完整包解压到原安装文件夹，保留原有config、appsettings和resource/image/UserStages，然后启动。无需新建目录或打开旧助手；启动模块自动完成图片迁移。之后的版本才可持续使用程序内更新。

已经经由旧更新器删掉的截图，须从旧目录或备份恢复；不能凭关卡元数据重新生成图片。

## 数据范围

| 旧版资料 | 导入内容 |
| --- | --- |
| `config/` | 全局偏好、全部实例、设备连接、任务勾选、任务选项、自定义关卡元数据等文件 |
| 根 `appsettings.json` | 实例列表、顺序、当前实例及原生定时设置 |
| `userdata/resource/image/UserStages/` | 活动入口截图、关卡截图和附属页面标记；自动兼容旧资源中的image/UserStages，保留子目录及文件名 |

使用旧版 `interface.json` 解析资源位置，但不把它或旧运行代码、运行库覆盖到新版。仅旧安装目录内的绝对路径改为新版路径，外部模拟器与ADB安装路径保留。商城选项在前端读取配置前从磁盘迁移，其他选项按各模块的兼容规则处理。缺失选项使用界面默认值。

1.5沿用已保存的任务选项、输入数值和明确取消，不用新版默认值重置旧配置；自定义关卡两张截图及其他页面标记一起继承。新建商城任务使用当前界面定义的默认清单。现有商品清单（含空清单）和折扣开关保留。旧两组清单按商品名称分配到当前分组。固定禁用桃子及高价值调教道具属于资源保护，旧的允许珍贵道具开关不再生效。

## 可选的跨目录导入

仅在从另一安装目录导入资料时才使用旧向导。Windows用户关闭目标助手，在目标安装根目录创建名为 `.tkfm-import-request` 的空文件，再启动目标助手；向导在读取配置前出现。此时打开旧助手并保存设置、停止任务，向导每1.5秒自动检测来源；唯一来源直接选择，多个来源才需手选。

点击“导入并结束旧助手”后迁移资料。取消、Esc或关闭均不结束旧助手、不改配置，并消费本次导入请求。正常启动不再依赖旧的一次性展示标记，也不会要求反复打开旧助手。

## 完整性与失败处理

1. 从所选旧进程读取完整可执行文件路径，核对名称、启动时间和进程句柄；当前进程、同目录及相互包含的目录不能作为来源。
2. 暂存所有资料并核对复制内容和自定义截图引用。配置损坏、截图缺失或权限不足时显示原因，不开始替换新版数据。
3. 资料可读取后只结束该旧助手进程，重新读取最后落盘文件；不结束模拟器、游戏或其他助手。
4. 在新版 `backup/config-import-*` 中保留被替换的资料，再将配置和图片一起导入；失败时回滚已经替换的部分。旧目录及原文件始终保留。
5. 导入完成后才继续打开新版主界面。用户检查设备、任务选项和定时任务后使用；工具本身不运行游戏任务。

旧助手未保存到磁盘的修改无法保证继承。关闭旧助手使用精确进程终止，不依赖可能阻塞的退出确认。导入阶段暂时禁用取消，避免写入一半后继续启动；导入前可随时取消。系统断电、磁盘损坏或回滚也受权限影响时仍需手动从备份恢复。

## 手动迁移

跨目录导入不可用时，关闭两边助手，先备份旧目录，再将旧 `config/`、根 `appsettings.json` 复制到新版相同位置；将旧 `resource/image/UserStages/` 或 `userdata/resource/image/UserStages/` 合并到新版 `userdata/resource/image/UserStages/`。若旧 `interface.json` 指向外部资源，以实际资源为准。不要复制旧版整个资源目录覆盖新版流程。

## 实现入口

`tools/first_run/StartupHook.cs` 负责读配置前入口；`UserDataMigration.cs` 自动备份、迁移旧图片、核对引用并补缺失默认值。`first_run.ps1`和`import_config.py`仅负责主动请求的跨目录导入。`tools/install_first_run.py`接入桌面包；`tools/install.py`与CI排除用户文件；`tools/run_dev.ps1`为开发环境安装同一启动组件和持久资源路径。
