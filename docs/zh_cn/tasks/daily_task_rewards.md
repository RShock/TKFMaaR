# 奖励领取（DailyTaskRewards）

入口 `DailyTaskRewardsStart`；实现为 `daily_task_rewards.json`、`agent/task_rewards.py`，强化前置见[角色强化](daily_character_upgrade.md)。两个账目只在最外层初始化一次，恢复、重启及复查均不重新发放次数。任务通过[统一异常恢复](task_recovery.md)包装，返回主页只是导航恢复，不能代替完成六页领取。

## 前置与完成条件

- 游戏已解锁任务页，可从主页或已知恢复页面开始。
- 先强化两次，每次最低级药水一瓶；强化账目独立，领奖恢复不重复强化。
- 页签顺序：每日、每周、每月、个人、活动、协会；全部处理后再复查一轮，每页两轮累计最多领取三次。
- 每页两次间隔确认：完整任务页、正确选中页签、一键领取实图和不可领取颜色均存在，没有可领取条目、遮挡或待确认请求，才允许切页。
- 六页通过后由 `DailyTaskRewardsReturnMainFromTaskPage` 返回并确认主页。包装器要求本轮确实命中该完成路径，不能仅因恢复子流程正常返回就报告成功。

## 按画面处理

各页领取及完成复查共用 `[JumpBack]DailyTaskRewardsHandleResponse`：

1. 已知仓库上限或奖励弹窗：识别正文／标题和完整确定按钮图片，点击按钮精确中心；保留响应种类，回到同一页后再核对。
2. 有待确认请求且重新识别到当前页：`DailyTaskRewardsObserveClaimPage` 调用明确动作核对响应，不在识别回调中修改账目。两次观察至少间隔500ms，期间不重复提交或切页。
3. 识别到无遮挡主页和任务图标时，业务分发通过 `DailyTaskRewardsOpenFromMain` 重新打开任务页。待确认请求优先回对应页签，其余情况重查上次领取页或每日。确认任务标题和一键领取按钮后才选页，重入保留已用额度和未确认请求。
4. 仍在加载或等响应：继续按当前画面检查正常与已知异常候选。未知画面20秒后才允许导航兜底；返回后重新进入上述分发，不困在已过期的等待节点。
5. 无弹窗、无待确认请求且页面可领取：预占一次额度，再点击一键领取图片中心。额度耗尽仍有奖励时明确失败，不能当作全部领完。

初次进入和恢复重入合计最多发出三次入口输入。点击前重新截图，识别主页右上任务图标和无遮挡主页。首次点击图标中心。画面仍是主页且距上次输入至少2.5秒时，可以按住同一识别中心120毫秒后松开。日志记录实际输入方式和结果，任务标题和一键领取按钮同帧命中后另记已到达任务页。

## 奖励响应与识别

| 目标 | 识别与约束 |
| --- | --- |
| 主页任务图标 | `Common/MainTasksIcon720.png`，取自模拟器故障截图。匹配范围集中在主页右上角，图标模板避开大部分通知红点。 |
| 任务标题、六页签、一键领取 | `Common/`实图，页签兼容选中／未选中，一键领取兼容亮／灰，仅用于定位；默认阈值0.85，不全局加严 |
| 奖励标题 | 复用 `DailyAlchemyOrders/RewardTitle720.png`，在弹窗上半部查找 |
| 入库说明 | OCR“奖励已增加至仓库／獎勵已增加至倉庫”，ROI `[210,600,300,270]`，覆盖已观察的纵坐标781等不同高度；无可靠说明模板，保留OCR |
| 奖励确定按钮 | 复用炼金及网络提示的完整按钮实图，ROI `[235,650,250,300]`；必须同帧命中奖励标题或入库说明，并排除真实服务器异常及仓库上限 |
| 仓库堆叠上限 | 多行OCR去空白标点后联合核对堆叠上限与物品／仓库语义，再用原确定按钮模板定位 |
| 可领取、已领取 | 列表区域OCR；后者是变化的业务状态，用于比较领取前后条目数量，不定位点击 |

不再按“紧凑／展开”两种固定纵坐标分开奖励处理，也不再仅凭OCR“确定”关闭未知弹窗。旧节点名保留兼容，统一复用同一语义识别和按钮中点动作，不参与重复候选扫描。每页同类弹窗至多关闭六次，跨重启保留，按钮不响应也不会无限点击。

请求通过以下任一证据加两次完整当前页观察结清：

- 已识别奖励或仓库上限响应，且弹窗已关闭。
- 错过短暂弹窗，但列表中“已领取”条目较点击前增加。
- 当前页按钮不可领取且列表无可领取文字。

仍没有这些证据时，不以输入成功或单纯返回原页确认到账。原请求满20秒后，若还有领取额度且两次确认同一页无遮挡，允许释放本次未知请求、重新扫描剩余奖励；原次数保持已用，日志明确“未确认，不记成功”。这仅适用于不消耗资源的领奖，不推广到商城、强化或调教。最后一次额度仍未能核实，或画面未知时，沿用故障设置。所有完成判定仍要求六页独立检查，不能以有限重试替代完成证据。

完整页判断统一排除奖励、仓库上限、完整确定按钮、加载、服务器异常、退出游戏和返回标题确认遮挡；未知弹窗不能透过背景页签放行。

## 每日堆叠上限例外

仅每日允许部分跳过：本轮三次领取额度用尽、至少一次每日请求确实出现仓库上限、最后请求已由可靠响应或实际页面进展核实，并连续两次确认每日页无遮挡。记录“每日部分奖励因堆叠上限未领取”，继续其他页签；第二轮共用这份账目。未确认重试不提供上限或最后响应证明，普通页签没有这条例外。

异常恢复不重新初始化、不重置购买或消耗次数；已知异常按同帧画面处理，系统返回逐次检查主页，所有本地续接失败才交统一暂停／唯一重启策略。
