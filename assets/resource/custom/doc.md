# 前端资源扩展

## 每日政务与体力入口

- `TkfmRunWithRecovery` 支持可选 `initialize` 节点，在首次业务尝试前仅执行一次；游戏重启与局部恢复不重新初始化，保留每日政务预占次数及待确认提交。
- `DailyAffairsInitialize` 额外接收当前实例 ID、配置目录和日志目录，供 Agent 按实例读取、补录和保存三项扫荡日期。
- `TkfmCustomStage` 只覆盖 `DailyStaminaBattleStartAttempt` 和原关卡路由。共同入口 `DailyStaminaStartAttempt` 先处理已开启且到期的政务。
- 空闲迁移只补战争演习、情报搜集、商业经营三个缺失的默认开启选项，保留已有明确值；开发迁移脚本行为一致。新建队列读取三个开关，运行中修改下次队列生效。

## 启动游戏与模拟器

- “启动游戏”的复选框用独立的灰底白勾模板，禁用点击且不跟随主题强调色。批量取消和预设改动也保持勾选，任务名称仍可打开设置。列表回收控件或卸载时恢复原模板。
- “启动游戏”集中提供定时执行所有日常任务和两个公用模拟器启停开关。时间使用电脑本地时区。模拟器选项不提供型号、编号、程序路径或额外问号。
- 手动队列的“启动游戏”确认所选游戏已经在前台时，先短暂复用正向识别的恢复动作。每次点击后复核当前页面，允许连续处理战斗结算、地图和普通子页。找到无遮挡的出征即完成。探测未命中直接进入正常启动分发，探测过程静默且不触发故障策略。
- 定时运行先确认所选 ADB 设备。已就绪则直接复用。开启自动启动且设备未就绪时，优先沿用已保存的启动程序，其次根据设备信息自动识别。Android 启动就绪后才运行队列。不得切换到另一个设备。
- “测试自动启动”共用定时启动代码。仅确认设备关闭且助手空闲时可点击。测试只准备模拟器和 ADB，结果显示在按钮下方。
- 仅已成功结束的定时队列可以按开关关闭模拟器。关闭前确认原设备、设备占用和单实例关闭能力。当前实现有 MuMu 管理命令和 Android Emulator 控制台；无法确认时保留现场并记日志。

- ADB 已连接但「当前控制器」没有选中项时，按本实例活动设备显示名称、地址及可用的实例编号。选中项或断开状态恢复后沿用原生显示。显示补位不触发扫描、重连或切换设备。

## Windows 后台运行

- Windows 最小化固定进入任务栏，关闭窗口固定进入托盘。右键托盘图标选择「退出」结束助手。隐藏窗口时继续运行当前任务和定时队列。「设置 → 界面设置」保留开机自启动选项，默认关闭。
- 开机自启动按当前用户和安装路径保存，Windows 登录后启动并收进托盘。普通启动仍显示窗口。真正退出和系统关机沿用前端的退出清理。开发启动脚本通过对应 PID 的本地退出通知请求空闲实例退出，运行中的实例不自动中断。

## 任务上次运行状态

- 按助手实例及任务 ID 保存最近一次实际运行的结果（完成、失败、停止）与本地显示时间，包括“启动游戏”。历史跨天和重启保留，空闲任务在历史时间前标明「上次」。本轮排队或跳过时显示「排队中」或「本轮未执行」，运行时显示实时耗时。故障暂停时任务行显示「故障暂停」，隐藏转圈和耗时。
- 开始运行时先保存开始时间。重启恢复时，未记录结束结果的任务显示“运行中断”及开始时间。正常结束后保存结果和结束时间。
- 兼容旧版成功记录的 ISO 时间及带日期的 `HH:mm`。读取 ISO 时间时保留原字符串。列表重建保护只影响界面更新，运行记录照常写入。
- 按电脑本地日期显示任务行历史。任意状态的非当天日期用红色，时间和状态文字保持默认颜色。当天完成用绿色。
- `TkfmDailyCompletion` 在协会奖励入口读取周末开关，手动队列和每日定时队列共用。工作日跳过以实例、本轮 ID 和任务项识别，队列继续运行，任务行显示「本轮未执行」，实际完成历史保留。

## 加载与兼容

## 体力药水到期提醒

- 最后一项实际排入队列的任务开始前，使用当前实例的共享控制器截取一帧。主画面「菜单」上方的红色底栏及「时」字同时命中才记录提醒，倒计时数字可以变化。
- 本轮队列结束后输出一次红色日志「体力药水即将过期，请自行处理！」。最后一项被中止、画面不含倒计时或取图失败时跳过提醒。检查过程只取图和识别。

- 使用 MFAAvalonia 2.16.2 自带的 C# 自定义动作加载器，连接初始化时编译本目录顶层 `.cs`，无需修改 EXE 或另装匹配库。按钮在资源及连接初始化后出现。
- `TkfmLogLimit` 与 `TkfmDeveloperSettings` 仅作为扩展入口注册，不加入任务流程，不执行设备动作。变更后重新启动开发版；重复加载须释放旧定时器及事件订阅。

## 关于

- TKFMaa 不启用「帮助改进软件」。`TkfmDeveloperSettings` 关闭原生 Sentry 遥测并隐藏「关于」里的整张卡片，资源 Interface 不提供接收地址。本地日志及故障截图沿用原配置。「关于」不显示「使用教程」，启动迁移同时让前端跳过首次使用教程。

## 运行中修改配置

- `TkfmRuntimeSettings` 开放任务普通／高级选项及游戏设置中的输入控件，不修改运行状态、队列、当前Pipeline或控制器。原生队列启动时已序列化全部任务选项，因此购买清单、扫荡／体力开关、次数及关卡选择在下次启动队列生效；运行中保存仍走原生持久化。任务列表的增删、排序与启停沿用原生保护。
- 输入控件使用可释放的IsEnabled优先值覆盖原生Idle锁，保留底层绑定；只覆盖实际输入，不覆盖父级选项条件或输入模板内部控件。自动派遣启用时手动时间区域等业务禁用条件继续生效；资源重载释放覆盖与提示，异常只记录一次，不能定时刷日志。
- 自定义关卡配置在对应步骤进入时读取并生成不可变图片引用：运行中允许新增、编辑、采图和保存，尚未进入该步骤时读取最新配置；已进入的步骤及其恢复继续原图片和体力消耗，重录不覆盖旧文件，删除不清理仍可能引用的图片。关卡选择仍属于队列选项，下一队列生效。
- 故障行为和失败后继续策略在每个模块入口读取；运行中编辑仅影响后续尚未开始的模块，当前模块及重试不变。每日定时保存即时生效，已登记的单次派遣继续使用登记快照。界面说明各自生效时点，不增加确认弹窗。
- 连接中的实例仍暂时禁止编辑关卡，实例关闭后拒绝保存。设备切换、服务器资源切换与重新连接沿用原生运行保护，不能借配置编辑解锁销毁当前控制器；后台配置迁移仍只在空闲执行。

## 自动配置迁移与可选旧版导入

- 桌面发布包另装 `tools/first_run/` 的 .NET StartupHook，在前端读取配置和检查更新前自动备份、迁移，不依赖设备连接。config与appsettings仍在同一安装目录；用户图片迁入userdata/resource/image/UserStages，第二资源包保留原UserStages相对引用。缺失默认键才补值，失败停止启动，保留备份和旧图。
- 正常启动和升级不弹旧助手向导；仅Windows用户主动创建安装根目录的 `.tkfm-import-request` 后，下次启动才显示跨目录导入。保留原libloader和前端二进制。
- 用户同时打开旧助手后，按进程目录和 TKFMaa/TKFMaaR 元信息每1.5秒自动检测来源；唯一旧助手无需选择，多个时才显示选择列表。点击导入后仅结束该来源且路径、启动时间均匹配的旧进程。先暂存并核对，再结束旧助手，重新读取落盘资料、备份新版资料后导入。取消和关闭均不结束旧程序。
- 跨目录导入完整迁移 `config/`、根 `appsettings.json`、旧资源的 `image/UserStages/`，图片统一写入userdata，包含关卡入口图、关卡图及页面标记；不把旧界面定义或运行代码复制回来。缺失的图片引用或无法读取的配置必须明确报错。
- 自动迁移状态为 `.tkfm-userdata.json`，备份在 `backup/userdata-*`；可选导入的历史标记为 `.tkfm-first-run-migration.json`，备份在 `backup/config-import-*`。流程和首次从1.5接入的限制见[配置迁移](../../../docs/zh_cn/tasks/config_migration.md)。

## 更新源与更新渠道

- 启动自动检查资源版本，资源仓库和反馈元信息只指向 `RShock/TKFMaaR`；不向Fork前原项目查询。`EnableCheckVersion` 默认true；`EnableAutoUpdateResource` 默认false，可自行开启且后续不强制重置。不开启自动安装时由用户确认更新；`EnableAutoUpdateMFA`保持false，前端/native统一由项目完整包维护。
- 复用原生同目录更新；发布包排除config、appsettings和用户截图，默认设置由启动模块仅补缺项。旧更新器的文件事务只解决失败回滚，不保护放在resource中的私有图片；图片须放userdata第二资源包。禁止重新将维护者config或截图打入发布包。
- `TkfmForkUpdateCheckV1`保留历史迁移标记；新启动模块仅补缺失默认值，不用该标记强开用户明确关闭的检查。开发脚本对旧策略的首次修复仍保留。GitHub下载源由首次初始化及扩展固定；旧进程已锁定的检查或已删除的图片不能靠远端发布补救。
- 开发者设置随连接初始化把前端下载源固定为 GitHub，并清理 `DownloadSourceIndex` 与 `DownloadCDK`；更新页隐藏下载源下拉框、CDK、购买链接、到期提示及 Token 输入和链接。更新匿名访问 GitHub，继续支持代理和资源更新操作。不能只隐藏 Mirror 选项而不改已保存索引，否则仍可能从 Mirror 下载。
- 资源更新渠道仍是前端可见的 Alpha、Beta、Stable。三者不是不同分支，而是同一仓库 GitHub Release 的筛选条件：Stable 排除预发布，Beta 接受 beta 与 stable、排除 alpha，Alpha 接受全部；当前 UI 更新渠道控件由固定前端自身隐藏。
- MFAAvalonia 2.16.2 的发布工作流按 `v*` tag 创建同一仓库的 GitHub Release，tag 含 `-` 时标记为预发布。因此可用 `alpha`、`beta` tag 表示内测、公测，正式版用不带后缀的 tag；不能把“公测版/内测版”描述成独立代码分支。

## 启动阶段误报

- MFAAvalonia 2.16.2 的自动连接只用于加载资源，却会把空任务队列的 `onlyStart` 流程显示为“任务已全部完成”；`TkfmStartupLogFix` 在扩展加载时消费该次完成提示，用户下一次主动启动任务时由前端正常重置状态。
- 启动和空闲时继续更新实时预览，空帧只表示预览暂未就绪，不发出空画面警告。任务实际执行时恢复原生空画面诊断。执行前的 ADB 重连继续处理真实连接失败。
- 扩展沿用固定前端 2.16.2 的预览定时器及状态字段，卸载时恢复原生回调。升级前端时复核回调与字段，缺失时跳过扩展补丁。

## 统一截图

- 同一实例的任务识别、实时预览、自定义关卡采图与派遣倒计时共用一个原生控制器及其缓存；保留当前 MuMu `EmulatorExtras` 取图方式及 720×1280 基准，取消独立预览控制器，不新增 ADB 截图进程或桌面截图路线。
- 使用 MFAAvalonia 2.16.2 原生 `UseSeparateScreenshotTasker=false`：预览读图、提交截图及重置均由前端复用主控制器，独立截图 Tasker 不再创建。内置备用实现留在固定前端二进制中，不修改 EXE/DLL。
- 开发启动迁移在前端启动前逐实例备份并写入该设置；不能被旧 `TkfmGameOptionsV2` 标记跳过。`TkfmStartupLogFix` 构造时同步设置，空闲刷新补充新实例；运行或暂停中的原生任务不热切换控制器，已有双连接须重新启动清理。
- 任务截图返回状态必须先确认成功，再读取缓存并进行识别；截图失败明确提示尚未执行当前任务，不能以耗时统计完成当作拿图成功。自定义关卡继续只读实时画面缓存，派遣倒计时继续读取上一识别帧，均不增加独立连接。

## 自动启动与服务器

- “启动游戏”位于任务列表首位。“资源类型”直接选择工口服务器（内部ID官服，`com.pinkcore.tkfm`）或erolab服务器（`com.pinkcore.tkfm.erolabs`），共用资源目录。
- `TkfmRunWithRecovery` 在真实队列首次执行模块前用所选ADB路径、序列号查询pidof及前台Activity；未运行才启动并登录，后台进程只切回前台，查询失败不当作已运行。
- 游戏进程已存在时直接执行当前任务，不再运行 `GameLoginEnsureReady`，不先返回主页或等待广告；仅在后台时切回前台，不结束游戏。未运行或故障策略要求重启时才走登录分发，看到无已知遮挡的“出征”即完成，不要求广告出现或关闭。广告晚到、公告及左上返回均交给统一异常恢复；队列内完成进程准备后复用标识。
- 自动启动与定时派遣统一读取 `processor.Config.AdbDevice`，与前端创建控制器使用的路径、地址及 MuMu 元信息一致。实例配置中的 `AdbDevice` 在内存可能是 `AdbDeviceInfo`，不能用 `GetValue<JObject>` 读取，否则会退回空对象并误报配置缺失；不覆写设备配置或自动切换设备。
- 每次队列的新取消令牌触发新检测；只连接资源和只登记未来派遣不启动游戏。派遣关闭游戏后清除准备标识，后续模块重新准备。ADB查询10秒超时，响应停止，隐藏命令窗口。
- 空闲时迁移旧启动行的服务器索引，保留可手动执行的“启动游戏”任务，将征才旧开关子项次数提升到任务直接选项，数值不乘四；重复征才步骤各保留自己的次数。开发启动先备份并迁移实例JSON，发布环境由扩展补做迁移。

## 商城分组选项

- 商城配置通过启动模块在前端读取实例设置前迁移。读取磁盘保存的任务行，保留现有商品选择、折扣开关和明确取消，包括全部取消。缺失选项沿用界面默认。

- 五组沿用原生复选框和绑定；TkfmShopOptionsUi只在任务选项标题上方插入横向分隔线，幂等安装，扩展释放时移除，不替换选项控件。仅扫描TaskQueueView内对应标题，不改日志或其他任务的布局；异常最多记录一次。
- 常用道具不显示“只购买打折”，招募命令、紧急录用证和初级体力药水按勾选结果直接购买；材料、属性石和调教道具组仍显示各自的“只购买打折”。其他组独立显示召唤契约、阿克色、魔晶石、银币、银币打折五项，不设组统一折扣开关；魔晶石默认勾选，勾选后复用已有MagicCrystal图标与名称图片且不限折扣。阿克色仅修改新配置默认值，不取消用户已保存的选择。
- 常用道具和协会其他分组移除已废弃的折扣选项和策略缓存。银币不限折扣与仅折扣使用不同商品节点和固定策略，选中两项仍沿用同卡去重及售罄保护。
- 新建商城任务默认选中招募命令、初级体力药水、两种材料、全部属性石和调教道具，以及召唤契约、魔晶石和银币打折。材料、属性石和调教道具默认只购买打折。

## 统一异常恢复

- 只按账目等待的节点以`attach.recovery_response_wait: true`声明；包装器在这类候选之前插入已知异常识别，不依赖某个Python处理器的私有名称和mode。领奖与强化各自在Pipeline声明等待边界，新增等待无需继续修改公共C#名单。
- 奖励领取各页共用响应分发；返回主页后由业务页签续接，不回到过期等待直接失败。响应账目、每页领取额度与两次强化始终保留，包装器要求本轮命中六页完成后的返回节点。普通返回动作仅改变页面，不能清除请求或当作业务成功。
- 开始页、网络重登提示及“是否离开游戏？”走独立登录接管：每任务最多两次、每次90秒绝对时限，外层任务初始化、游戏重启保留。`TkfmRunWithRecovery` 的 `mode: resume_login` 只运行有界子状态机，不递归初始化业务、不结束游戏进程；须新增命中 `TkfmRecoveryLoginSucceeded` 才算恢复成功，加载和反复识别不延长时限。
- 战斗结算页联合识别「返回地图」模板、再次挑战和结算文字，点击返回地图中点。启动登录、登录接管、业务失败和返回主页恢复共用该节点，最多点击两次。动作后重新识别实际页面，保留业务账目。
- 网络提示同帧确认「提示」标题和「确定」按钮实图，优先查找「网络不稳定，将重新启动游戏」的正文模板，网络异常及跨日等不同文案可走 OCR 复核。两次登录接管均按本次命中后的计数执行，第 2 次仍可点击确定并继续登录。开始页联合局部TAP TO START英文OCR与左上固定工具图标实图，不再凭Ver或固定版本号放行；离开弹窗用正文及取消按钮双图，只点取消中心。已知登录目标存在时禁止系统返回，即使登录额度耗尽也交故障策略。
- 登录子流程复用公告、广告和签到的原识别目标及动作，使用独立有限导航次数，普通弹窗额度耗尽不阻止新登录；每次网络确定最多两次、开始最多五次、退出取消最多三次，广告／公告／活动签到各三次，月卡恰好一次，均受90秒总时限约束。只回到无遮挡主页后才交还原业务；不等待广告出现。
- 征才登录恢复保存开始前的待确认提交证据；恢复后招募中／待录取沿原记账，连续两次确认空栏才撤销未生效许可并恢复本栏导航。总次数、刷新与加速额度不重发，未核实提交前禁止一键收取；未知状态不重招。
- `non_retryable_hit` 本轮新增命中时直接进入最终失败策略，可用 `non_retryable_reason` 指定原因。

- 新增返回标题确认框恢复：同帧匹配“是否要回到标题画面？”正文及取消按钮实图，点击取消图片中心，不选择确定；计入现有每任务两次共享额度，重启保留。包装器将对应Observed加入业务未命中后的识别，并在错误出口优先于导航返回；正常登录分发也处理此弹窗，主界面完成判断排除此遮挡。系统返回保持原有逐次发送和每次主页检查，已到主页不发下一次。
- 登录网页故障是直接重启特例：Agent先检查同帧连续64×64纯白，再OCR“网页无法打开”。包装器在业务候选及异常候选前注入非JumpBack终止分支，命中后不再点击业务按钮、弹窗或系统返回键，即使普通故障设为暂停也请求重启；记录识别词组和后果。每模块入口清零网页信号，重试保留信号计数，子任务按新增命中判断失败，不能把子流程结束视为完成。
- 网页故障只使用模块现有的一次游戏重启额度，覆盖首次自动启动及恢复登录；已用额度后再命中则明确失败并沿用最终停止／跳过策略。其他已知恢复保持并列候选，全未命中才逐次发送最多三次安卓系统返回，然后执行设置中的暂停／重启，不清业务账目。

- 已知异常恢复全部不命中后，追加 `[JumpBack]TkfmRecoverySystemBack`：每次发送一次安卓系统返回键4，再识别当前步骤，每任务最多三次，已识别主界面时禁止发送。此额度独立于原两次已知恢复，初始化仅在外层任务开始；游戏重启保留命中计数，不更改故障策略或业务账目。
- 派遣通过 `home_retry_prefix` 启用返回主页恢复。业务回退均未命中时结束当前流程，最多发送三次安卓返回键，每次都检查主页。返回流程从现有游戏画面确认主页，重启流程通过启动并登录确认主页。两者共用导航重置、入口重跑和结果处理，保留资源账目及已用恢复额度。每轮最多重跑一次。

- 注入恢复分支时兼容源码字符串和 `GetNodeData` 返回的 `{name,jump_back,anchor}` 路由对象；按字段判断重复入口，保留原有属性，不能把整个 `next` 用 `Values<string>()` 转换，否则任务开始即抛出类型异常，尚未进入识别就触发故障暂停。调度异常须在磁盘日志记录完整堆栈。
- 魔王月卡页同帧识别四字标题与底部TOUCH SCREEN实图，只点击TOUCH SCREEN中点一次，再进入 `GameLoginDispatch` 复用启动页面处理：公告识别标题后点击下方空白点 `[360,1155]`，广告点击左上箭头中心，确认无遮挡出征才返回原步骤；不重新启动游戏，不等待广告出现。公告和广告各沿用登录节点最多三次限制。`GameCloseSignIn`与`TkfmRecoverySignIn`共享单次额度，任务开始初始化、游戏重启前保留，并计入总恢复额度；通用TOUCH SCREEN点击排除此标题，防止绕过限制。
- 每轮先识别正常业务，未命中立刻检查已知异常；两类连续20秒未命中才进入原异常出口、完整返回及最多三次系统返回，再按故障策略处理。仅有账目条件的响应等待之前插入已知异常候选，不让它吞掉弹窗；正常识别与异常识别同帧执行，不额外截图。
- 服务器异常／跨日提示使用中部“提示”标题、完整“确定”按钮的同帧实图及特有正文OCR复核，进入独立登录接管，点击确定中心后继续登录，确认无遮挡出征后跳回原步骤。登录接管每任务两次，重启前后保留；不结束游戏进程，不重新初始化业务账目，耗尽仍沿用故障策略。
- 任务异常时依次识别公告、活动签到、完整左上返回按钮和广告箭头；识别到返回按钮就点击图片中心，再跳回原步骤按当前画面继续。普通完整按钮只用于超时后的导航兜底；广告须箭头及精选、月卡页签同帧命中，不能把普通业务页返回误报为广告。公告关闭后需要继续登录时可使用返回或城堡回主页，看到出征即可，不要求广告出现。
- 普通返回与三类弹窗共享每任务两次额度，包含兼容登录路由的返回，重启前后保留；返回只负责导航，不清业务账目、不等于任务完成。
- 正常业务候选后即检查公告标题、活动签到“结束时间”、月卡与TOUCH SCREEN组合及广告；命中Observed入口后才转共享恢复节点。两类连续未命中20秒后再检查完整返回及系统返回。提前广告检查要求箭头与精选、月卡页签实图同帧命中；普通页面和广告可共用完整返回按钮，不据此区分；普通业务提示不得只凭“提示／确定”模板进入登录。活动签到和月度签到点击后进入登录分发器，处理连续出现的登录遮挡，确认无已知遮挡的出征后再跳回原步骤；不能关闭第一张签到页后立即判断商城。普通返回仍直接跳回原步骤；没有已知目标时先尝试上述有界系统返回，耗尽后交回原异常出口。
- 普通弹窗每个任务合计最多两次恢复点击，广告、公告、活动签到与普通返回共用额度；开始页及网络重登使用上述独立有界登录接管，包含兼容登录路由的返回及箭头兜底，游戏重启前后不重置。局部恢复不重新执行模块初始化、不清除业务命中次数、anchors、商城购买记录或资源额度；关闭失败仍执行原故障策略。公告继续登录路由，看到出征即可完成；活动签到页在正常登录分发器中也会处理，不等失败再关闭。
- 开发版和发布版共用启动阶段的商城迁移。旧两组清单按商品名称分组。新配置按界面定义加载商品和折扣默认值。
- `TkfmRunWithRecovery` 包装所有公开任务及保留的活动入口。原入口名保持稳定，原页面状态机移到同名 `Attempt` 主体；模块内部回跳必须指向主体，不能递归进入恢复入口。
- 弹窗关闭或返回后仍不能继续当前步骤时，再按故障行为消耗唯一游戏重启额度：结束所选渠道的游戏进程，重新启动并完成原登录确认，再从当前模块入口重做。登录任务自身重做已包含结束与启动，不叠加第二次重启。模拟器和助手保持运行。
- 同一步骤再次异常、恢复登录失败或恢复调度错误时不再重启；按下述故障行为处理，失败步骤仍记为失败。手动停止不触发恢复。连接、资源加载及扩展编译发生在模块外，不能由本动作恢复。
- 游戏设置新增“开发者选单”，按实例保存并包含“遇到故障时行为”。故障行为下拉框提供“重启/暂停”：重启默认开启并保留旧 `TkfmRestartFailedStep` 配置迁移，弹窗恢复仍失败后最多重启一次；暂停在弹窗恢复仍失败后冻结在节点边界并等待用户点击“继续任务”或停止。
- 原继续运行开关改名为“重试后仍异常时继续下一步骤”，关闭表示停止全部任务；缺少旧配置时默认关闭，已有明确值保留。行为下拉框允许执行中修改，每个模块入口读取一次，当前模块及其恢复沿用开始时的设置。
- 包名读取本实例“资源类型”的服务器选择；两渠道的冷启动与重启后登录均识别无已知遮挡的“出征”，不等待广告。恢复登录的 `GameMainReady` 必须自然结束子任务，不能使用会传播到父任务的 `StopTask`。
- 重试前清理页面导航命中计数，保留体力药、体力购买和调教次数额度及既有 anchors。征才以 `TkfmRecruitmentAttempt1..100` anchors逐次记账，保留待确认动作和领袖状态；批次完成节点及Gate不再作为总额度，恢复不能重新发放次数。
- 已知弹窗命中可直接恢复，未知画面连续20秒后走兜底恢复分支，模块返回失败后才执行原暂停／重启策略；正常体力不足等原有正常完成条件保持正常。异常出口必须明确失败，不能用成功的 `StopTask` 遮盖错误。日志注明首次失败、唯一重启、重试结果与最终停止或跳过策略。
- 入口可通过 `success_any_hit` 声明本轮必须命中的完成节点；包装器比较调用前后命中次数，Pipeline 以 `on_error` 安全返回主页但未命中完成节点时仍返回失败，避免静默跳过。
- 未注册到任务列表的旧 `AutoBattleStart` 依赖人工进入活动列表，重启后无法自动重建这一前置状态；重试必须继续识别列表，不能只因回到主页就报成功。实现与限制见 [统一异常恢复](../../../docs/zh_cn/tasks/task_recovery.md)。

## 暂停与继续任务

- 在普通及紧凑布局的原生开始/停止按钮左侧注入“暂停任务”按钮；任务运行时显示，暂停后文字变为“继续任务”。
- MaaFramework 5.x 没有原生 tasker 暂停 API。扩展在同步 `Node.*.Starting` 回调边界使用可恢复闸门冻结下一步识别、动作或等待，不调用 StopTask，因此保留当前任务队列和 Pipeline 命中状态。
- 继续任务只解除闸门并原地恢复；点击原生停止时，在停止按钮命令处理前释放闸门，避免暂停状态阻塞停止。任务结束、连接替换或扩展释放时同样自动放行。
- “遇到故障时行为=暂停”复用同一闸门，并在统一恢复动作内等待用户继续；解除后当前步骤仍返回失败，不伪装成成功，也不自动重启游戏。
- 暂停发生在事件边界而不是强制挂起线程；当前已开始的截图、识别或点击允许完成，下一次节点开始前不会再推进。实现不修改前端 EXE，也不重启游戏。
- 故障暂停保留失败页面供定位；例如购买点击已发出但详情仍在，应检查实际落点与后续状态机，不能仅因游戏画面未改变就认定 ADB 已断开。商城购买中心点击及有限重试由商城 Agent 和 Pipeline 处理，暂停服务不自动补点。

- 设置页顶部显示原版设置说明及「导出错误日志」。桌面导出组件汇集最近 72 小时的前端日志、框架轮转日志和 `debug/on_error` 故障截图，保留文件原文并生成单个 ZIP，Windows 打开资源管理器并选中 ZIP。
- 故障截图始终开启。任务首次失败、重启登录失败、重试失败或恢复调度出错时，在恢复动作前写入磁盘日志并尽可能保存当前控制器缓存帧。任务取消不触发此记录。
- 按前端本地化消息匹配并隐藏连接失败通知。原生连接失败详情继续写入文件，资源及其他错误通知照常显示。

- 直接使用MFAAvalonia原生日志控件、绑定、格式与滚动逻辑。删除TkfmDetailedLog、自定义列表替换、滚动回调、历史镜像、显示快照及原生事件重复格式化／写盘；不再提供“开发者详细日志”开关，旧配置字段不启用任何逻辑。

- 原生可释放集合负责释放被删除行；扩展重载释放旧计时器，裁剪异常每次加载最多记录一次，不循环输出错误。
- 普通日志文件与MaaFramework原生日志沿用前端原有机制，已存在的logs/detailed文件保留，不继续写入自定义JSONL。业务模块原有的征才选词、商城诊断与异常恢复提示保留。

## 定时派遣

- 派遣抽屉等待、总览扫描或发队后异常恢复回到主页时，重新识别出征实图，并排除抽屉队伍文字及已知遮挡，再点击固定比例入口[35,630]打开抽屉；同一任务最多六次，等待时已在总览直接进入扫描，沿用本轮派遣进度。抽屉已打开时根据各队状态继续处理。
- 手动执行“每日派遣”直接运行。三队都在派遣时保存下次时间。只有开启自动最速派遣才会到点运行。开启时先使用仍有效的已算时间，否则登记首轮派遣。「每日派遣」的【任务设置】提供自动最速派遣开关。仅开启时显示任务名旁的时钟和设置里的取消按钮。时钟悬停显示下一轮本地时间或预约状态。【任务说明】仍显示实时预约状态及培养建议。
- 到点先持久化领取状态并核对原 ADB 程序和地址。设备正在运行其他任务时等待空闲。失败、停止或离线错过的已登记预约不会补跑。
- 定时运行按所选服务器重新启动游戏并处理遮挡，识别到无遮挡主页后继续。派遣子任务自然结束后再处理模拟器关闭和下一次预约。

## 消耗体力内的自定义截图关卡

- 自定义关卡在刷取前、回列表时读取画面顶部 10%–20% 的活动分数并记日志。默认启用防溢出。界面在可编辑的 `150` 后固定显示 `000`，保留已有输入值。距完整上限 3,000 分时停刷，命中时跳过尚未执行的政务与刷图。能识别分数的活动在保护开启时从结算返回列表复查，扫荡使用弹窗初始数量，识别到多次时拒绝提交。

- “使用扫荡券”默认不勾选；标准关卡详情经 `DailyStaminaStageDetailModeDecision` 分流，普通战斗复用 `TkfmCustomStage` 的 `mode: direct` 子流程，识别开始、再次挑战及体力不足退出。直接战斗必须沿用显式用药、购买开关和额度，不受扫荡不足补刷开关限制；勾选时才启用扫荡入口、设置与开始节点。内置日常调教和仅有开始按钮的关卡继续原直接战斗路线。
- 自定义关卡属于“消耗体力”，不注册独立任务，不在日志标题栏、游戏设置中放入口。连接初始化、扩展加载后，扩展“体力消耗关卡”现有下拉框，显示内置关卡、本实例各份自定义关卡和“添加自定义关卡…”，同一选项下提供“管理自定义关卡”。
- 内置选项只保留“日常调教本”，过期活动和战争演习预设移除；自定义配置继续支持添加和删除。旧内置索引归到调教，带稳定配置ID的自定义选择归到自定义存储项，不按旧索引误选其他关卡。
- 自定义关卡的录制和运行固定走“限时活动”。旧页签选项失效，保留配置和图片。入口录制在冻结的缓存帧中复用页签文字模板和亮线识别，使用无控制器的独立识别任务，不占用当前游戏队列。
- 内置Cases仍由active.yaml生成，生成器仅在末尾追加固定存储项**TKFM_CUSTOM_STAGE**；本地命名配置不写回Interface或YAML。原生任务Option保存固定索引，并在“体力消耗关卡”Option.Data的custom_stage_profile_id保存稳定配置ID；任务级CustomStageConfig.attach.profile_id用于当前会话合并。界面把这个存储项展开成多份可读名称，重命名不影响关联。删除已引用配置显示缺失并拒绝执行，不退回其他关卡。
- 自定义动作只会在自定义Case被选中时运行；任务级profile_id为空时，回退到实例TkfmCustomStageProfilesV1.selected，兼容旧配置或前端未保存覆盖的情况。回退不改变内置关卡选择，因为内置Case不会进入该动作。
- 每实例保存多份配置，支持新增、重命名、复制和删除。“保存并使用此关卡”同时保存配置并选入打开编辑器的消耗体力步骤，其他步骤维持原选择。编辑器有固定在右上角的 ×。编辑器与截图窗口均有“不保存并退出”，并支持Esc：截图取消不返回新选区、不覆盖原截图；编辑器退出丢弃尚未保存的修改，不撤销此前已保存的内容。退出按钮不随取帧、冻结或任务忙碌禁用。编辑页直接列出已保存配置和新草稿，截图缺失也可选中。删除需二次点击确认，确认后按 ID 立即保存删除。旧独立自定义任务在空闲加载时转换为消耗体力任务并保留原配置引用与资源开关。
- 活动入口和关卡截图必须复用`MaaProcessor.GetLiveViewCached()`返回的右侧实时画面缓存帧，不得另启动`adb.exe`或建立第二套截图链路。窗口每500ms尝试复制缓存，上一帧处理未结束时跳过，不积压取帧任务；源缓存没有新画面时不承诺真实2fps。用户在游戏中切页，点击截取冻结后拖框并确认。后台刷新保留已显示帧的截取能力，冻结后的在途刷新不得覆盖选区底图。未连接或尚无有效帧时提示并等待主动刷新；不自动切换设备。运行中允许编辑与采样，连接中暂不可编辑；关闭／取消停止计时器、取消在途任务并释放预览，重载释放窗口、计时器与订阅。
- 9:16实时画面缓存归一到720×1280后无损裁剪，预览窗口大小不参与基准。选区不少于16×16且位于列表区域；关卡截图另保存顶部[50,60,600,80]作为页面标记。复用MaaFramework TemplateMatch，0.85为阈值，不代表实测准确率。
- 图片使用不可变随机目录保存在安装目录userdata/resource/image/UserStages/，第二资源包加载并保留UserStages相对引用；启动模块自动兼容旧资源中的图片。元数据仍使用实例TkfmCustomStageProfilesV1，保留旧数据。复制可共享不变图片，删除不物理清理图片，避免破坏引用。图片由Git忽略，备份同时保留实例配置和图片目录。
- 配置不完整、图片损坏或缺失、非法体力消耗、路径越界在动作前失败，不重启游戏。导航分两段：命中限时活动选中状态及活动入口后点击，再进入关卡列表路由。若从录制的列表直接启动，先返回活动页确认限时活动。
- 出征、限时活动页签、活动入口与关卡目标均使用TemplateMatch并操作识别框精确中点，不传矩形给原生Click随机落点，不以OCR定位。出征默认方法及阈值0.82保留，通过`CustomStageEnterExpedition`复用中点点击；已知遮挡存在时不进入。自定义任务直接进入当前画面路由，主页入口最多六次；每次由主页输入出征后只恢复限时活动页签的三次导航额度，保留列表下滚及体力账目。限时活动页签用文字实图联合底部亮线ColorMatch判断选中，已选中或已在关卡列表时不重复点击；未选中时仅此处中心按压150毫秒，下一轮仍须识别实际页面。入口和关卡各三次，各路由节点最多命中三十次；输入成功不代表切页成功。
- 新自定义配置的单次体力消耗默认 35。列表替代控件只复制普通样式类，禁用等伪类由新控件自己维护。
- 限时活动有单独「进击」按钮时，先确认用户配置对应当前大图，或同帧确认凯萨½左侧卡片、下方选中标题及用户入口图，再点「进击」。进入后确认关卡列表才能选关。
- 同一实例内保存同名配置时覆盖原项并沿用其 ID，名称去除首尾空白且忽略大小写。保存校验所选及修改过的配置，其他已保存配置缺图时可照常保存。
- 入口截图必填，关卡截图可省略或清除。无关卡截图时，按钮下方随输入显示按体力随机找关说明。15、25、35使用实图数字模板，未提供模板的体力显示红字并在执行前失败。旧截图配置沿用原路径和页面标记。
- 接入活动分数复查时，保留运行时 `next` 中的节点对象及跳回、锚点属性，兼容字符串节点。
- 关卡截图和指定体力数字共用地图搜索。确认列表后先找当前屏，再依地图视野右 2、下 6、左 2、上 6、右 2、下 6 逐次滑动。每滑一次重新匹配，六段结束仍未命中时报选关失败，保留地图现场。手势与地图方向相反，沿用 370 像素和 700 毫秒。体力模式用左上返回和右上兑换确认地图。
- 分数保护回列表时允许续选对应体力，无需重复初始随机下滑。选图失败、体力模板未找到和关卡未解锁均由原失败策略处理，不触发重启。未知画面仍走异常恢复。
- 可用的军团扫荡复用既有扫荡与补刷。扫荡按钮模板、灰色底纹和「开始」同帧命中时优先进入普通战斗，适用于未通关关卡。仅有「开始」时也直接战斗。体力消耗继续按配置比较，用药及购买沿用消耗体力现有显式开关和额度。导航或战斗异常沿用一次重启恢复。
- 点击目标后在弹窗正文区域 OCR 识别「活动进度需完成…后开启」。命中时保留弹窗、记录未解锁并走不可重启的失败出口，由原故障策略决定暂停、停止或继续后续任务。
- 活动须在点入口后直达可上下滑动的列表，额外分类、横向分页和自动编队未覆盖。指定图的顶部标记变化、截图包含动画或倒计时需重新录制。未主动要求测试时不运行测试，不把生成配置或界面启动当作实机验证。

## 派遣倒计时续约

- `DailyDispatchStart` 的 `custom_action_param` 必须显式传 `{}`。Maa 对缺省参数传出 JSON `null`，`TkfmDispatchSchedule` 必须把参数解析及全部执行逻辑放在异常保护内；任何异常只能返回失败，不得逃逸到 native callback 并终止 MFAAvalonia。
- 左侧抽屉从同一帧逐栏读取三条非零倒计时，并排除“派遣完成”和“闲置中”后直接确认本轮完成。抽屉读数不齐时进入总览核对。总览按三队派遣中及取消按钮确认完成，并从同一帧读取三条倒计时。完整读数用于按最长值加 5 秒计算下次时间。
- 每实例保存一份已算时间或待执行预约。关闭自动派遣时，已算时间只供显示。预约到点等待设备空闲。取消按钮关闭本实例的自动最速派遣，撤销等待或准备中的预约。已进入任务队列的本轮继续执行。只有本轮成功才保存新的时间。
- 独立预约仍在收尾时，普通队列派遣算出的新预约随旧记录保存。恢复旧预约临时改动的设置后再启用新预约，沿用其设备和登记时的会话，避免丢失倒计时或补跑离线期间错过的预约。

## 配置每日定时

- 每天按设定时间运行当前配置中勾选的任务。默认 17:30，支持逗号分隔的多个 `HH:mm`。助手运行时遇设备忙碌，合并等待中的同配置触发，空闲后执行。休眠和退出期间错过的时间不补跑。
- `TkfmDispatchSchedule` 共用两个定时入口，临时停用原生换设备、重连启动和任务前后动作。队列结束后恢复。每日队列逐项确认成功才关闭模拟器。
- 前端启动模块在 ADB 离线时也加载调度扩展。旧实例的原生每日启动时间迁入新面板，再关停对应原生时间点，避免双重执行。

- 调教详情按选中通用／活动页签定位，避免半透明标题随动画漏检。广告的冷启动和任务恢复共用三项正向识图；异常关闭动作每次后立即跳回原业务，不在广告分支中连续点击返回。未知画面20秒后仍允许普通返回及逐次最多三次系统返回，不清资源账目。
